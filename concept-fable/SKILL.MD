# Concept Fable Skill

写一篇有阅读欲望的中文故事稿，把研究生水平的概念藏在人物选择里。先让故事自己成立，再让概念在结尾补上一刀。默认生成封面图，并把成稿保存到 `G:\fable`。

## 默认假设

- 用户指定概念时，用指定概念；没指定时，挑一个历史中没用过、机制能被故事演出来的概念。
- 默认写中文，面向中文长文读者；可以借鉴知乎盐选的“故事带知识”阅读感，但不要冒充平台内容。
- 默认输出 Markdown 到 `G:\fable`，封面图同目录保存为 `-cover.png`。
- 标题、封面提示词和故事正文在揭晓前都不能出现概念名。
- 文章不要像模板填空。连续两篇不能使用相同叙事容器、时代背景、核心道具或揭晓句式。

## 工作流

1. 读取历史：创建 `G:\fable`（如不存在），读取 `G:\fable\concept-history.md`，并扫描 `G:\fable\*.md` 中的 `## 原来它讲的是：...`。
2. 避开重复：建立已用概念集合，也记录最近文章的叙事容器、场景和核心道具。
3. 选概念：选择一个未用过、能用因果链演出来的概念。如果用户指定的概念已用过，提醒后换相近但未用过的概念；除非用户明确要求重复。
4. 选叙事容器：先决定这篇文章长什么样，再写内容。不要默认古镇寓言。
5. 写故事：让人物先有自己的麻烦、私心、误判和难堪。概念从他们的选择里长出来。
6. 揭晓概念：揭晓必须自然，像读者忽然对上，而不是老师开始上课。
7. 改稿：使用 `write-like-human` 的检查思路重写一轮，删除 AI 腔、金句腔和固定结构。
8. 生成封面：用 Codex 内置 `image_gen` 根据故事核心画面生成封面，保存到 `G:\fable`。
9. 保存和登记：写入 Markdown、封面、历史记录，并检查三者都存在且非空。

## 概念和写法去重

每次生成前建立两个集合。

概念集合：

- 读取 `G:\fable\concept-history.md` 中的概念条目。
- 扫描 `G:\fable\*.md`，提取 `## 原来它讲的是：<概念>`。
- 中英文名视为同一个概念，例如 `辛普森悖论` 和 `Simpson's Paradox` 不能分别再用一次。

写法集合：

- 从历史记录和最近文章里提取叙事容器、时代背景、核心道具、人物关系。
- 连续两篇不要重复：古代集市、师徒、账本、榜单、桥、掌柜、徒弟、收摊后顿悟。
- 如果最近 3 篇都偏“旧时代寓言”，下一篇必须换到现代或半现实场景。

生成成功后，追加一行：

```text
- yyyy-MM-dd HH:mm | <中文概念名> (<English Name>) | <标题> | form=<叙事容器> | setting=<场景> | prop=<核心道具> | <文章文件名>
```

旧历史记录没有这些字段也能继续使用；有字段时优先参考字段。

## 选题池

从不同领域轮换，不要连续使用同一类概念：

- 统计 / 概率：遍历性、回归均值、生存者偏差、鞅与最优停止、大数定律的误用、选择偏差
- 物理 / 复杂系统：自发对称破缺、重整化、相变与临界点、涌现、模拟退火、涨落耗散
- 经济 / 博弈：委托代理问题、公地悲剧、科斯定理、柠檬市场、囚徒困境、道德风险
- CS / 信息：奈奎斯特采样与混叠、偏差-方差权衡、CAP 定理、no free lunch、停机问题
- 数学 / 逻辑：哥德尔不完备、对角线论证、不动点、测度零、贝叶斯更新

已在历史里出现过的概念，不要再选。

## 叙事容器

每篇先选一种容器。容器决定文章的呼吸，不只是换皮。

可用容器：

- 现实短篇：职场、家庭、医院、学校、直播间、二手平台、创业公司、投资群、工厂夜班。
- 非虚构口吻：我听来的事、旧案复盘、一次访谈、匿名投稿、会议纪要背后的故事。
- 档案体：信件、聊天记录、判决书摘录、审计报告、维修单、客服工单、病历边角。
- 寓言体：可以用古镇、船、桥、铺子，但连续几篇后要停用。
- 反向叙事：先给结果，再一点点暴露前面的选择怎么把人推到那里。

禁用默认套路：

- 不要总是“老师傅 + 徒弟 + 账本 + 结尾一句话点题”。
- 不要总是“红榜/白榜/集市/掌柜/收摊”。
- 不要总是“他以为自己赢了，其实输了”这种同构标题。
- 不要每篇都在结尾用一句漂亮金句收束。

## 标题

标题要像真实内容标题，而不是论文题目，也不是模板标题。

- 不出现概念名。
- 少用“为什么”；能不用就不用。
- 少用“最”“底层逻辑”“终极真相”“深度解析”。
- 可以有一点别扭感、冲突感或人情味。

标题方向：

- `她把最好的客人赶走以后，生意变好了`
- `那个没人敢接的单子，最后救了整家公司`
- `他给所有人发了奖金，第二天就没人干活了`
- `那张便宜保单，只卖给了最危险的人`

## 故事写法

故事要先好看。概念只是最后让它变亮的东西。

- 开头直接给压力：钱不够、名额快没了、病人等着、客户退单、老板催、家里有人不说实话。
- 人物要有不体面的动机：怕丢脸、想省钱、想证明自己、想糊弄过去、想对某个人有交代。
- 对话要像人说话。允许打断、含糊、嘴硬、沉默和半句没说完。
- 细节必须具体，但不要堆砌。一个发凉的外卖盒、一张被揉皱的单子，胜过一段抽象心理描写。
- 段落长度要变化。紧张处短，转弯处慢。
- 不解释隐喻。读者看得懂。
- 不要在故事里写“这说明”“这象征”“这背后体现”。

## 揭晓和解释

解释部分不再强制固定小标题。根据文章气质选择一种形式：

- 后记式：作者把故事翻回来，指出真正的误判。
- 案件复盘式：像复盘事故一样拆出关键机制。
- 旁白式：先承认一个直觉，再说明它哪里错。
- 附录式：主文结束后，用短小的表格或模型补齐概念。
- 访谈式：让一个人物在事后说出他当时没看懂的东西。

必须做到：

- 揭晓句可以是 `原来它讲的是：<中文概念名> (<English Name>)`，但不要每篇都用同一种句式。
- 先说最刺人的误判，再给概念名。不要一上来写百科定义。
- 至少给一个小模型、数字例子或现实类比，让概念站住。
- 如果使用表格，只用在它真的省字的时候。不要机械放“故事元素 -> 概念元素”。
- 扩展词条表可选。用户要学习地图时再加；默认不强制。

## Write-like-human 改稿

保存前必须做一轮 `write-like-human` 检查。目标不是润色得更漂亮，而是删掉机器味。

重点删除或重写：

- 三段式排比和整齐列表。
- “不仅……而且……”“不是……而是……”这种过度对称句。
- “这提醒我们”“这说明了”“本质上”“底层逻辑”等讲课腔。
- 可引用金句。如果一句话像海报文案，改得更朴素。
- 过多的“然而、此外、因此、值得注意的是”。
- 每个段落都用同样节奏收尾。
- 人物只为概念服务的桥段。补一个具体动作或删掉。

自检标准：

- 大声读一遍，像不像人在讲一件事。
- 连续三个段落是否都是“场景 -> 对话 -> 心理 -> 转折”。
- 解释部分是否像 Wikipedia。像的话改成具体误判。
- 有没有地方在替读者总结情绪。能删就删。

## 封面图生成

写完故事后生成封面。封面是故事入口，不是概念图解。

- 使用 Codex 内置 `image_gen` 生图能力，遵循 `imagegen` skill 的默认 built-in tool mode。
- 不要要求用户设置 `OPENAI_API_KEY`；缺少 `OPENAI_API_KEY` 不是跳过封面的理由。
- 生成后把最终图片保存或复制到 `G:\fable\<同前缀>-cover.png`。不要让 Markdown 引用只指向 `$CODEX_HOME/generated_images/...`。
- 建议横版；如果用户指定平台比例，按用户指定。
- 封面不放概念名、不放解释文字、不放水印、不放平台 Logo。
- 画面只抓一个最有张力的故事瞬间。

提示词结构：

```text
Use case: illustration-story
Asset type: Chinese narrative knowledge essay cover image
Primary request: Create a cinematic narrative cover illustration based on this story: <用 2-4 句概括故事核心画面，不出现概念名>
Scene/backdrop: <具体地点和时代感>
Subject: <主要人物/物件/冲突>
Style/medium: refined editorial illustration or realistic cinematic illustration
Composition/framing: landscape cover, strong focal point, room for title overlay if needed
Lighting/mood: <情绪和光线>
Constraints: no concept name, no explanatory diagrams, no watermark, no platform logo, no random text
Avoid: generic stock-photo look, overdramatic fantasy, cyberpunk, cluttered typography
```

## 文档结构

只固定必要骨架，不固定解释模板：

```markdown
# <标题>

![封面](./<同前缀>-cover.png)

> <一句有钩子的引子；不透露概念名>

<故事正文>

---

<揭晓和解释。形式随文章而变，但必须讲清概念、误判、小模型或现实类比。>
```

可选模块：

- `## 事后再看`
- `## 这件事真正卡在哪里`
- `## 一个很小的模型`
- `## 想继续查`

不要每篇都用同一组模块。

## 保存规则

- 输出目录：`G:\fable`
- 文章文件名：`yyyyMMdd-HHmm-<安全化标题>.md`
- 封面文件名：`yyyyMMdd-HHmm-<安全化标题>-cover.png`
- 历史文件：`concept-history.md`
- 安全化标题：去掉 Windows 文件名非法字符 `\ / : * ? " < > |`，空白压缩为一个空格。
- 写入后检查文章、封面和历史文件都存在且长度大于 0。
- Markdown 中的封面引用使用相对路径：`![封面](./<同前缀>-cover.png)`。
- 最终回复只给标题、文章路径、封面路径、概念和一句说明。

## 成功标准

- 本次概念不在历史已用概念集合里，除非用户明确要求重复。
- 本篇叙事容器、场景和核心道具没有复用最近文章的套路。
- 标题吸引人但不剧透概念。
- 故事先行，人物不是概念工具人。
- 揭晓后读者能把故事和概念对上，但没有被硬灌课。
- 已完成 `write-like-human` 检查，删掉明显 AI 腔和公式结构。
- 封面图基于故事核心画面生成，不剧透概念，不带错误文字。
- 成稿、封面和历史记录已保存到 `G:\fable`，并经过非空检查。
