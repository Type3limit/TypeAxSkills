---
name: network-check
description: 检查本机网络并进行优化
---

请帮我进行「网速检查及针对性优化」，必须严格遵守以下流程：


你只能先做检查，不能一开始就修改任何网路设定、删除 profile、关闭程式、改 DNS、改 MTU、重启服务或更动 VPN。
目标：
1.找出是否有可以提升网速、降低延迟、改善稳定性的地方。
2.先产出诊断报告，列出每个问题的证据、可能原因、预期改善幅度与风险。
3.在取得我的明确批准前，不得执行任何优化动作。
4.优化后必须做 before/after 对比，确认是否真的变好。


请按照以下阶段执行：


第一阶段：只读检查，不修改设定
-检查目前网路介面、预设路由、DNS、Proxy、VPN、MTU。
-检查是否正在使用 VPN，以及 VPN 是否可能造成高延迟或 DNS 变慢。
-测试 DNS resolution time，分别比较系统预设 DNS、路由器 DNS、VPN DNS，如适用。
-测试封包遗失与延迟，例如到路由器、公网 IP。
-检查 Wi‑Fi 讯号强度、Noise、SNR、频道、连线速率与可能干扰。
-检查是否有明显吃频宽的背景程序，但不要 kill 或 throttle。
-如需跑 speedtest、networkQuality 或任何会大量使用网路流量的测试，请先告知可能消耗流量并询问我是否同意。
-如遇到需要更高权限的只读命令，请先说明用途再请求批准。


第二阶段：诊断报告
请用简体中文输出报告，格式如下：
1.检查摘要
-目前是否有明显瓶颈
-主要问题排名
-是否建议优化
2.发现的问题
每个问题请包含：
-问题描述
-证据，例如 latency、DNS query time、packet loss、Wi‑Fi signal、VPN route
-对网速的可能影响
-风险等级：低 / 中 / 高
-是否值得处理
3.不建议动的地方
-例如 MTU 正常就不要改
-mDNS 没有证据拖慢上网就不要优化
-network profiles 不确定用途就不要删
-DNS 若被 VPN 接管，不要盲目改
4.建议优化方案
请按照「最可能有效、最低风险」排序。
每个方案请包含：
-要做什么
-为什么值得做
-可能风险
-如何还原
-预期改善的是下载速度、网页反应、延迟还是稳定性


第三阶段：等待使用者批准
在执行任何优化前，请明确问我：
「你是否批准执行以下优化项目？」
并列出每一项将会执行的操作。
未经我批准，不得执行：
-修改 DNS
-修改 MTU
-删除 network locations / profiles
-关闭、kill 或 throttle 背景程序
-重启网路服务
-关闭或切换 VPN
-flush DNS / mDNS cache
-更改 Wi‑Fi 或路由器设定


第四阶段：执行已批准的优化
只执行我批准的项目。
每个改动前，请先用一句话说明你即将做什么。
每次只做一类改动，做完后立即检查结果。
不得顺手清理无关设定。


第五阶段：验证
优化后重新测试：
-DNS resolution time
-latency / ping
-packet loss
-Wi‑Fi 状态
-如我批准，执行 speedtest 或 networkQuality
-比较 before/after 结果
最后请输出：
-哪些项目真的改善了
-哪些项目没有明显改善
-是否建议保留改动
-是否有需要还原的项目
-下一步建议
额外限制：
-VPN 功能必须保持可用；除非我明确批准，不得关闭、切换、重连或改变 VPN 设定。
-若发现主要瓶颈来自 VPN，请先提供「不碰 VPN」的替代方案，并清楚说明改善幅度可能有限。
-优化优先顺序：稳定性 > 延迟 > 下载速度；不得为了速度牺牲安全性或必要功能。
-若某项检查需要 sudo 或高流量，必须先说明可获得什么证据，以及没有该证据时报告会有哪些限制。
