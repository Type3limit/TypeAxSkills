# Project Discover — 详细规范与模板

本文件是 `project-discover` 的深层参考。SKILL.md 给流程骨架，这里给可直接复用的模板、话术与命令。

---

## 1. 可参考的社区范式

组合这几套思想（可向用户解释「为什么这么设计」）：

| 范式 | 借鉴点 |
|---|---|
| **Anthropic Agent Skills** | 三级渐进：元信息常驻 → 正文按需 → bundled 资源再按需。本知识库就是它的"项目版"。 |
| **llms.txt**（llmstxt.org） | 根目录一个精选索引，链接到可展开的 markdown；"先读索引、按需顺链接"。 |
| **Cursor Rules**（`.cursor/rules/*.mdc`） | frontmatter `description`/`globs` 条件加载；本库用 `load_when` 实现同样的"按需判定"。 |
| **AGENTS.md 标准**（agents.md） | 单一开放入口格式，Codex/多工具识别；用作通用 agent 入口。 |
| **Diátaxis** | 区分讲解 / 操作步骤 / 参考，决定 L2 文档怎么归类。 |

设计落地：`llms.txt 式索引`（README 路由）+ `Cursor 式 load_when`（条件加载）+ `Skills 式三级渐进`（入口→路由→主题→深度）。

## 2. 第 1 步要问用户的决策

用 AskUserQuestion 一次问清（答案决定成品形态）：

1. **文档深度**：① 骨架全建 + 高确定内容写满、其余标 TODO 逐步补（省前期 token）；② 多 subagent 一次性深读所有模块、写满实现逻辑（一步到位、前期开销大）；③ 只建路由骨架、内容按需补。
2. **入口覆盖**：① CLAUDE.md + 通用 AGENTS.md（推荐）；② 再加 `.cursor/rules/*.mdc` 镜像；③ 仅 CLAUDE.md。
3. **与既有 doc/ 关系**：① `.rules` 只索引+链接、`doc/` 原位不动（推荐）；② 把 doc/ 内容迁入 `.rules`。

## 3. `.rules/` 目录树模板

按目标仓库的真实分层调整 `core/ui/...` 这层命名。典型：

```
.rules/
  README.md                 # 路由总表（agent 永远先读）：场景表 + 全量清单 + 使用协议 + 维护约定
  overview.md               # 产品 + 架构 + 对象图 + 构建命令 + 术语速查（先手写，作格式范本）
  conventions.md            # 代码风格 / 文件命名编码 / 核心机制硬约定（undo、错误处理等）
  <layerA>/*.md             # 按业务/技术分层的 L2 主题文档（架构、各模块、序列化…）
  <layerB>/*.md
  integration/*.md          # 外部系统/后端集成、协议、ABI 耦合点
  features/*.md             # 跨模块的特性专题
  migration/*.md            # 进行中的架构迁移（状态+索引页，链到既有计划）
  workflows/*.md            # 操作清单：build-verify、add-<thing> 等
```

L0 入口（`CLAUDE.md` / `AGENTS.md`）只加一段「文档导航」，指向 `.rules/README.md` + 3~4 个高频链接，保持极小（常驻、便宜）。

## 4. 每篇 L2 文档的统一规范

**frontmatter（YAML）**：

```yaml
---
title: <中文标题>
load_when: <一句话：什么任务/问题时该读这篇——给 agent 路由判定用，写"触发条件"而非泛泛标题>
reads: [本篇覆盖的关键源码文件/目录，相对仓库根]
see_also: [相关 .rules 或 doc/ 文档的相对路径，全库统一一种写法]
updated: <YYYY-MM-DD>
---
```

**正文 6 节（按需取舍，保持顺序）**：
1. 职责（一句话这模块干嘛）
2. 关键类型/文件地图（表格：符号/文件 — 角色）
3. 核心流程/实现逻辑（数据流、调用链、关键不变量；引用真实符号）
4. 关键约定/坑（生命周期、线程/锁、易错点）
5. 扩展点/常见改动入口（"要做 X 改这里"）
6. 相关文档（先链同级 `.rules/`，再链 `doc/`，**只链接不复制**）

**硬规则**：
- 全用目标项目的叙述语言；标识符/类名/路径/枚举值保留原文。
- **引用代码用 `符号名（文件）`，绝不写行号**（不写 `:NNN`、`/NNN`、`（:NNN）`、散行号）。
- 不复制既有 `doc/` 深度内容，只链接。
- 拿不准写「（待核实：源码中未找到 XXX）」，绝不编造。
- markdown 普通 UTF-8（无 BOM）；链接用相对路径；贴代码片段 ≤ 10 行。

## 5. subagent 深读派发模板

按模块分簇，每簇一个 subagent（如"代码库入职引导工程师"），**并行派发**。每个 prompt 必含：

```
你在为项目 <名>（仓库根 <绝对路径>）撰写 .rules/ 工程知识文档，让其它 AI agent 不必重读源码即可快速定位。准确、可核对、能按符号名跳转是第一要务。

【第一步】先 Read <.rules/overview.md>，照它的 frontmatter 与版式写。
【你负责写】<明确列出 1-3 个文件的绝对路径>
【要深读】<列出该簇覆盖的源码文件/目录，省去探索成本>
【文档规范】<贴上第 4 节的 frontmatter + 6 节 + 硬规则>
【完整 .rules 规划树】<贴上全部计划文件名，约束 see_also 只指向这些>
【分工边界】<说明哪些内容归别的文档，避免重复>
完成后回报：写了哪些文件、各覆盖什么、读码时发现的与文档体系相关的重要事实或不确定点。
```

要点：① 给定要读的文件清单，别让它盲目探索；② 明确分工边界防重复；③ 要求回报"发现的事实偏差"——常能查出 CLAUDE.md/README 的过时描述。

## 6. 核对（verification）subagent 模板

代码会漂移（尤其会话期间用户提交了 commit）。核对一篇文档时：

```
你在核对 .rules/<文档> 与【当前源码】是否一致。背景：代码近期被改过（commit <hash> ...），符号可能被改名/移动/删除。
对文档引用的【每一个代码符号】（类/函数/枚举/成员/常量/文件）：
1. Grep/Read 在当前源码核实它确实存在、描述准确。
2. 被改名/移动/删除 → 修正文档为当前真实符号名/描述。
3. 【不要加回行号】；定位一律「符号名（文件）」。
4. 外科手术式：只改与源码不符处，其余 prose/结构/链接不动。
5. 确认无残留 文件:数字 行号。
回报：核实了哪些符号、哪些漂移已修正（旧→新）、哪些找不到已标待核实。
```

## 7. README 路由表结构

`.rules/README.md` 必含四块：

1. **给 agent 的使用协议**：先读 README → 按 `load_when` 判定 → 只 Read 命中的几篇 → 顺「相关文档」向下钻。强调"符号定位、不写行号；代码冲突以源码为准并顺手更新"。
2. **按场景定位表**：`| 我要做的事 | 先读 | 再按需读 |`——这是"我提需求 agent 快速定位"的核心，覆盖每个 L2 文档至少一行。
3. **全量清单**：按目录分组列出每篇 + `load_when`。
4. **维护约定**：每篇结构、符号定位不写行号、不复制 doc/、拿不准标待核实、改文档后更新两张表与 `updated`、改代码顺手校符号名。

## 9. 收尾 sweep 命令（确认无行号残留 / 无断链）

```bash
# 残留行号（冒号、斜杠、反引号内外、区间），排除日期/版本号误报后人工核对
grep -rEno '[A-Za-z0-9_]+\.[a-z]{1,10} ?[:/] ?[0-9]+|[`（(] ?:[0-9]+|`[:/][0-9]+' .rules --include=*.md

# 断链：每个 .md 链接相对其所在文件解析
cd .rules && for f in $(find . -name "*.md"); do d=$(dirname "$f"); \
  for l in $(grep -oE '\]\([^)]+\.md[^)]*\)' "$f" | sed -E 's/^\]\(([^)#]+).*/\1/'); do \
    t=$(cd "$d" && readlink -f "$l" 2>/dev/null); [ -f "$t" ] || echo "断链 $f -> $l"; done; done

# BOM 检查（.md 应无 BOM）
for f in $(find .rules -name '*.md'); do head -c3 "$f" | od -An -tx1 | grep -q 'ef bb bf' && echo "BOM: $f"; done
```

注意：脚本式去行号正则容易漏「反引号外」`` `file.cpp`:785 `` 与「散行号」`、`261`` 形式，且删 prose 内嵌行号会留病句——优先让 subagent 做 prose-aware 清理，脚本只做粗筛。

## 10. 验收标准

- 入口（CLAUDE.md/AGENTS.md）都指向 `.rules/README.md`，自洽。
- README 场景表 + 全量清单覆盖全部 L2 文档，无遗漏、无孤岛、无断链。
- 每篇 frontmatter 五字段齐全，`load_when` 路由可判定。
- 全库无残留行号；引用符号可在当前源码 grep 到。
- 端到端演练：代表任务 1-2 跳命中文档并落到真实代码。
